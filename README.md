# Tidepool — Slack-style collaboration on Firebase

A real-time team chat app: React + Vite + Firebase Auth, Realtime Database and Storage. No mock data — everything is read from and written to Firebase.

## Features
Google sign-in (persistent) and auto-created profiles · workspaces (create, switch, invite by email, roles Owner/Admin/Member, leave/delete) · public/private channels (create, rename, delete, join/leave, members, description, star, mute) · real-time messages (send, edit, delete, copy, links, multiline) · threads · emoji reactions with "who reacted" · mentions (`@name`, `@here`, `@channel`) · 1:1 DMs and group DMs · presence (online/away/DND/offline via `onDisconnect`) · typing indicators (ephemeral) · unread badges · in-app notifications (+ optional sound/desktop) · pinned and saved messages · file/image upload with progress, previews, paste-to-upload, client-side image compression · file browser · global search (Ctrl/Cmd+K) · profiles and custom status · settings (account, appearance, notifications, privacy, workspace) · light/dark/system theme and density · responsive layout with mobile drawer · offline/reconnect banner · skeleton, empty and error states · security rules for Database and Storage.

## Quick start
```bash
cp .env.example .env     # fill in Firebase values (see FIREBASE_SETUP.md)
npm install
npm run dev
npm test                 # unit tests (Vitest)
npm run build            # production build in dist/
```
Firebase console steps and deploy commands: **[FIREBASE_SETUP.md](FIREBASE_SETUP.md)**.

## Environment variables
`VITE_FIREBASE_API_KEY, _AUTH_DOMAIN, _DATABASE_URL, _PROJECT_ID, _STORAGE_BUCKET, _MESSAGING_SENDER_ID, _APP_ID, _MEASUREMENT_ID`. If unset, `src/firebase/config.js` falls back to the project from the brief. No Admin SDK credentials are used or needed.

## Project layout
```
src/firebase/    config, auth, database, storage (the only place Firebase is initialised)
src/services/    writes: messages, channels, groups, workspaces, users
src/contexts/    Auth, App (theme/toasts/modals), Workspace (live data aggregation)
src/hooks/       useValue, useMessageList (child listeners + limit), presence/online helpers
src/components/  ChatView, Message, MessageComposer, ThreadPanel, ChannelInfo, FileBrowser, SearchModal, ...
src/layouts/     AppShell, Sidebar          src/pages/  Login, WorkspacePicker, Settings
scripts/build-rules.mjs  → database.rules.json      storage.rules
```
Routes: `/login`, `/app/:wid/channel/:cid`, `/app/:wid/dm/:userId`, `/app/:wid/group/:groupId`, `/app/:wid/saved`, `/app/:wid/files`, `/app/:wid/settings`. Threads and side panels are URL query params (`?thread=<messageId>`, `?panel=info|pins`, `?msg=<id>` to jump) so they're linkable.

## Database structure (flat, denormalised)
```
users/{uid}                         profile, status, manualStatus
presence/{uid}                      {state, lastChanged}  (onDisconnect → offline)
userSettings/{uid}                  notification prefs
workspaces/{wid}                    name, description, icon, ownerId, createdAt
workspaceMembers/{wid}/{uid}        {role: owner|admin|member}
userWorkspaces/{uid}/{wid}          true   (index for the switcher)
invitations/byEmail/{emailKey}/{wid}  and  invitations/byWorkspace/{wid}/{emailKey}
channels/{wid}/{cid}                name, description, isPrivate, createdBy
channelMembers/{wid}/{cid}/{uid}    true
channelPrefs/{uid}/{wid}/{cid}      {starred, muted}
groups/{wid}/{gid}  userGroups/{uid}/{wid}/{gid}
messages/{wid}/{cid}/{mid}          senderId, senderName, senderAvatar, text, createdAt, updatedAt, edited, reactions/{emoji}/{uid}, attachments[], mentions[], pinned, replyCount
   cid = channel id | dm_<uidA>_<uidB> (sorted) | grp_<id>
threads/{wid}/{cid}/{parentId}/{replyId}
channelMeta/{wid}/{cid}             {count, lastMessageAt}   → unread = count − lastRead.count
lastRead/{uid}/{wid}/{cid}          {count, at}
typing/{wid}/{cid}/{uid}            {name, at}  (removed after 3 s idle and on disconnect)
pinnedMessages/{wid}/{cid}/{mid}    snapshot for the pins panel
savedMessages/{uid}/{wid}/{cid_mid}
files/{wid}/{fid}                   metadata + download URL (bytes live in Storage)
notifications/{uid}/{nid}           type: mention|thread|dm|group
```

## Security rules
`database.rules.json` is generated by `scripts/build-rules.mjs`. In short: default deny; you can only read a workspace if you're in `workspaceMembers`; messages/threads/typing/pins are readable and postable only by DM participants, group members, channel members (private) or workspace members (public); you can create messages only as yourself and edit only your own; admins/owners can moderate; reactions are writable only under your own uid; notifications are readable only by their owner; saved messages, settings and read state are private to the user; joining a workspace requires being the creator or holding an invitation for your verified email.
`storage.rules`: avatars (own folder, images < 5 MB) and workspace files (own uid folder, < 25 MB).

## Limitations (please read)
- **Not exercised against the live Firebase project.** The code was built, linted by the bundler and unit-tested with mocked Firebase only; I had no browser or Firebase access. Expect to do a first smoke test and report anything odd. The rules were reviewed by hand but not run in the Rules Playground — please simulate a few reads/writes after deploying.
- **Private channel names/descriptions are visible to every workspace member** (RTDB cannot filter a list per child). Their messages and member lists are protected. Group DMs are fully hidden.
- **Storage rules cannot check workspace membership** (they can't read the Realtime Database). Any signed-in user who has a file's long download URL can fetch it; URLs are only stored in data that members can read.
- User profiles are readable by any signed-in user (needed for DM search and mentions); "hide email" only hides it in the UI.
- Invitations are in-app, matched by Google account email — no email is sent (needs a Cloud Function / mail provider).
- Search runs in the browser over the latest 200 messages per conversation you can access, plus channels, people and files.
- Mention notifications and unread counts are per conversation; there is no separate "mention count" and no reaction notifications.
- Deleting a workspace removes channels, messages and invitations but not the uploaded Storage objects, and leaves group DMs created by others (use a Cloud Function for full cleanup).
- Presence "away" is tab-visibility based, not idle-timer based.
- Unread/typing use the client's clock for expiry; small clock skew can delay indicator hiding by a few seconds.

## Keyboard shortcuts
`Ctrl/Cmd+K` search · `Esc` close dialog/menu/drawer · `Enter` send (also Ctrl/Cmd+Enter) · `Shift+Enter` newline · `↑/↓ + Enter` pick mention/result.

## Troubleshooting
- *`auth/unauthorized-domain`* → add your domain under Authentication → Settings → Authorized domains.
- *`auth/api-key-not-valid`* → the API key is wrong (see note in FIREBASE_SETUP.md).
- *Permission denied everywhere* → rules not deployed, or the Realtime Database URL/region differs from `VITE_FIREBASE_DATABASE_URL`.
- *Uploads fail* → Storage not enabled, or storage rules not deployed.
- *Popup blocked on login* → allow popups for the site.
